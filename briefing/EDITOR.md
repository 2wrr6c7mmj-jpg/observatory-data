# 報道のまとめ：毎朝の台本の手順（台本を書く Claude 向け）

世界情勢観測の報道画面の「過去24時間のまとめ」を、**毎朝 08:00（日本時間）までに**公開する。
台本は Claude が書く。記事の束ね・選び方の候補・確かめ・音声・公開は、このリポジトリの `briefing/` と GitHub Actions がする。
決めた人：サイトの所有者（2026-11-24「あんたが書いて」「毎朝0800時に出したい」「なるべく情報の鮮度良く」）。

## 手順（07:26 に始まり、07:45 までに 4 を終える）
1. `main` を取得する。部品を入れる（公開の処理と同じ版。合わせて 1 分以内）：
   `python -m pip install -q fugashi==1.5.2 unidic-lite==1.0.8 lameenc==1.8.1 && bash tools/voicevox_setup.sh /tmp/vv`
2. 候補を出す（モデルは使わない。数秒）：
   `python -m briefing.editor candidates --feed https://observatory-watch.pages.dev/api/feeds --out /tmp/cands.json`
3. `/tmp/cands.json` を読み、台本 `/tmp/script.json` を書く（下の「選び方」「文の規則」「地図」）。確かめに通す：
   `python -m briefing.editor check --feed https://observatory-watch.pages.dev/api/feeds --script /tmp/script.json --vv-root /tmp/vv`
   「確かめに落ちた出来事 0 件」になるまで直す。直すのは 2 回まで。直らない出来事は外す。
   **毎朝かならず**：出てきた「読み」を全文読んで調声し（下の「調声」）、「地図」の行を出来事の場所と見比べる。
4. 公開を起こす（確かめ・音声・`docs/data/briefing/` への書き込みは Actions がする。約 2 分）：
   `gh api repos/2wrr6c7mmj-jpg/observatory-data/actions/workflows/briefing-publish.yml/dispatches -X POST -f ref=main -f "inputs[script_b64]=$(gzip -c /tmp/script.json | base64 -w0)"`
5. 実行の結果を確かめる（`gh api` で Briefing publish の最新の run の `conclusion` と check-run の注釈）。
   失敗なら注釈の理由を読み、台本を直して 4 をもう一度。**07:55 を過ぎたら何もしない**（前日のまとめが残り、画面は作成から 36 時間で出さなくなる）。
6. 報告は 3 行まで：件数・音声の長さ・外した出来事。異常が無ければそれ以上書かない。

してはいけないこと：コードや表（glossary・readings・places）の変更、PR、他のリポジトリへの書き込み、ここに無い外向きの操作。
直したい点を見つけたら、報告に 1 行書くだけにする。

## 台本の形
```json
{"version": 1,
 "readings": [["神舟", "シンシュウ", 0]],
 "events": [
  {"key": ["候補の key をそのまま", "…"], "headline": "24 字以内", "lines": ["1 文目。", {"text": "2 文目。", "kana": "調声したカナ"}],
   "map": {"countries": ["LY", "UA", "RU"], "name": "リビア", "place": {"name": "ベンガジ", "lon": 20.07, "lat": 32.12}}}
]}
```
- **重要な順**に並べる。全体は 120 秒が上限で、超えるぶんは後ろの出来事から外れる（7〜8 件が目安）。最大 8 件。
- `key` は候補の `key`（記事の id の頭）をそのまま写す。出典の数・分類・国・地点は、公開の処理が記事から取り直す。
- 同じ出来事の候補が 2 つ出ていたら 1 件にまとめ、`key` は両方から入れる。

## 調声（毎朝）
`check --vv-root` が、読み上げるとおりのカナを出す（`/` はアクセント句の区切り、`'` は音の下がり目、`_` は無声化）。**全文を読む。**
- 読み間違い（固有名詞・艦名・人名・地名・略語・数字の読み）は、台本の `readings` に `[表記, カタカナの読み, 下がり目の位置]` を足して直す
  （下がり目の位置は、読みの先頭から数えた拍の数。平板なら 0）。字幕の表記は変えない。足したら `check` をもう一度回して、直ったことをカナで確かめる。
- 読みの表（`briefing/readings.json`）に無い漢字の固有名詞は、まず疑う。2026-11-24 の例：「神舟」を「かみぶね」、「天宮」を「てんぐう」、「海警」を「うみ」と読んだ。
- **アクセントと区切り（イントネーション）**：カナを声に出して読むつもりで見て、下がり目の位置（`'`）と句の区切り（`/`）がおかしい文は、
  台本のその文を `{"text": "文", "kana": "直したカナ"}` にして直す。`check` が出したカナを写して、記号だけを直す。
  - 直せるのは記号（`'` `/` `、` `_`）だけ。読みそのものは変えられない（変えるのは `readings`）。字幕と違うことは読ませない。
  - 記法：どの句にも `'` が 1 つ要る（平板の句は、句の最後に `'`）。`、` は間の入る区切り、`/` は間の無い区切り。
  - よくある誤り（2026-11-24 の例）：名前どうしがつながって 1 句になる（宇宙船神舟 → `ウチュウセン'/シンシュウ'`、日本海上空 → `ニホ'ンカイ/ジョオクウノ'`）、
    複合語の下がり目（貨物船は平板 `カモツセンオ'`、負傷者は `_フショ'オシャ`、数十人は `スウジュ'ウニン`）、
    外来語の人名・地名（後ろから 3 拍目で下がるのが普通。ザポリージャは `ザポリ'イジャ`）、「人名＋役職」（報道官は `ホオド'オカン`）。
  - 自信の無い語は触らない（直したつもりで悪くしない）。`check` の行に「← 調声」が付けば採用。付かなければ記法の誤りか、読みが文と違う。
- 区切りがおかしくて聞き取りにくい文（長い漢語の連なり、助詞の無い名詞の並び）は、文を書き直してもよい（読点を入れる、「の」を入れる、2 文に分ける）。
- 声の設定（話す速さ・抑揚の強さ・高さ）は `briefing/voice.json` の `tune`。所有者が聞いて決める値で、毎朝は変えない。
- **文末（〜しました。〜しています。）は、合成のときに自動でそろえる**（`voice.json` の `ending`、`audio.settle_ending`）。
  文によって文末が高いまま終わったり、最後の拍が下がりきらなかったりするのを、どの文も同じ高さへ下げる。
  だから文末の句のカナは触らない。文は 1 文ずつ「。」で終える（文末がそろうのは 1 文の終わりだけ）。体言止め・疑問文は書かない。
- かぎ括弧は読み上げでは外れる（字幕には出る）。
- 続けて使う語は、報告に「読みの表に足す候補」として 1 行書く（表への追加は別の作業で入れる）。

## 地図（毎朝）
再生画面は、出来事ごとに地図をその場所へ動かし、国の輪郭と地点を出す。`check` の「地図」の行が、その出来事の行き先。
- 記事から機械で決めた値が**出来事の起きた場所**と違うときは、台本の `map` で直す。主体の国ではなく、場所の国を先頭にする
  （2026-11-24 の例：ウクライナがリビアのベンガジ港でロシアの軍艦を攻撃 → 先頭は LY、地点はベンガジ。機械の値はウクライナだった）。
- `countries`：輪郭を出す国（ISO 3166-1 の 2 文字、最大 3。先頭が地図の寄る先）。`name`：札に出す国・地域の名前（12 字以内。表に無い国はコードのまま出るので、そのとき書く）。
- `place`：点を打つ地点（名前と経度・緯度）。**記事に出ている地名で、位置が確かなものだけ**（都市・島・海峡・基地）。確かでなければ書かない（国の輪郭だけになる）。
  海の上の出来事は、記事にある最寄りの地名（島・港・海峡）を使う。推測で点を打たない。
- 出来事が特定の場所を持たない（声明・制裁・会談の予定など）ときは、国だけにする。

## 選び方
- 候補は、独立した出典の数の多い順に出ている。上から採るのが基本。3 源以上を優先する。
- 読者は、東アジア・中国の軍事の動きを追う人。出典の数が同じなら、東アジア、軍事・紛争を先にする。
- 1 つの国の配信元だけが報じた束は、軍事・紛争のときだけ採る（その国の経済・内政は採らない）。
- 同じ地域・同じ流れの出来事が 3 件以上になるなら、2 件までにする。
- 著名人の発言だけの話、スポーツ、芸能は採らない。
- 足りない日は件数を減らす。3 件に満たなければ公開しない（Actions が止める）。

## 文の規則
確かめ（`check`）が落とすもの：
- 見出し 30 字以内（24 字以内で書く）。1 件 1〜2 文、各文 15〜65 字、合計 110 字以内。「。」で終わる、です・ます調。
- 日本語でない文、英語のままの語（NATO などの大文字の略語と、Su-35 のような機種名は可）、URL・記号。
- 曜日、「今週」「昨日」「今日」「先月」、時刻（聞く日でずれる。日付が要るなら「11月24日」の形で、記事にある日付だけ）。
- 記事に無い数（3 桁以上、単位つきの数）・日付。万・億のつく数は記事と同じ値だけ（250 million は 2億5000万、2.5 million は 250万）。
- 出典で食い違う数の片方だけ（候補の `numberConflicts`）。全部を併記するか、書かない（記事にある「数十人」などの言い方は可）。
- 定訳に反する訳（候補の `terms` の「書かない」）。warship は「軍艦」（「戦艦」は battleship だけ）、naval mine は「機雷」。
- 原稿自身の評価の語（暴挙・卑劣・衝撃・当然 など）と、推測の形（…とみられる、…でしょう）。
- 非難・懸念・緊張・脅威・挑発などの語で、記事に対応する語が無いもの。
- 当事者が相手を呼ぶ言葉（海賊行為・侵略・テロ・虐殺・傀儡・戦争犯罪）が「」の外にあるもの。
- 紛争の出来事（候補の `needAttribution` が真）で、誰の発表・報道かの形（…と発表しました、…によると、…と述べました）が無いもの。

確かめでは拾えないので、書く側が守ること：
- **記事に在ることだけを書く。** 人名・役職・地理の説明・背景・見通しを、自分の知識で足さない（記事が古い・自分の知識が古いことがある）。
- 1 文目に、いちばん重要な事実を「誰が・何を・どこで」。主語は主体（国・組織・人）。
- 当事者の一方の発表（戦果・被害・相手の行為）は、発表した者を主語にして「…と発表しました」。攻撃した側が死者数を発表したように書かない。
- 役職は記事のとおり（副大統領・国務長官・事務総長・報道官を取り違えない）。記事に役職が無ければ「氏」。
- 国営・党系の配信元（候補の `kind`）だけが伝える内容は、「新華社は…と伝えました」のように配信元を主語にする。
- 防空識別圏に入ることは「進入」（「侵入」「侵犯」は領空のときだけ）。threaten to は「…すると警告しました」。
- 読みが怪しい固有名詞（韓国・北朝鮮の人名、中国の艦名など）は、カタカナで書く（読みの表 `readings.json` に無い漢字は読み間違える）。
- 名前は「」で括ってよい（字幕に出る。読み上げでは括弧を外す）。
- 声の規約（もち子さん）：特定の政治・思想・宗教や、それに属する個人・団体への応援・非難、誹謗中傷にしない。事実の伝達だけにする。

## 仕組み（参考）
- 候補：`briefing/editor.py`（`build.pick_candidates`）。過去 24 時間の記事 → 束ね → 2 源以上 → 順位 → 同じ出来事を除く、上から 12 件。
- 公開：`.github/workflows/briefing-publish.yml` → `python -m briefing --script`（`build.scripts_from_file`）→ 確かめ → VOICEVOX コア → `docs/data/briefing/latest.json`・`latest.mp3`。
- 画面（observatory-watch）は GitHub Pages の `data/briefing/latest.json` を直接読む。地図の動きは各出来事の `countries`・`place`、字幕は `lines`、切り替えの時刻は `start`。`hold` が真、または作成から 36 時間を過ぎたまとめは出さない。
- 止めたいとき：毎朝の定期タスクを止める（公開の処理は、定期タスクが起動したときだけ動く）。新しいまとめが出なくなり、
  いま出ているまとめは作成から 36 時間で画面から消える。すぐ消すには、加えて `docs/data/briefing/latest.json` の `hold` を `true` にする
  （これだけでは翌朝の公開が上書きする）。
