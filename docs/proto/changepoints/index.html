変化点と定義変更試作

週ごとの水準が段のように変わった時期（変化点）を自動で探し、日報の書式・定義の変更、および「記載のない日の割合」の変化点と同じ時間軸に並べます。報告の仕方が変わったのか、行動が変わったのかを見分ける手がかりにします。

何が分かるか

  • 値の変化点が、定義変更や「記載のない日の割合」の変化点と重なっていれば、まず報告の仕方の変化を疑います。重ならなければ、行動の変化の候補です（断定はできません）。
  • 変化点の日付の幅（ブートストラップの5〜95%）と、作り直したデータで同じ変化点が再び見つかる割合（再検出率）。

手法

  1. 週の系列：月曜始まりの週ごとに、値のある日の中央値を取ります（値のある日が4日未満の週は欠測）。1日だけの大規模演習に引きずられないよう、平均ではなく中央値にしています。
  2. 変化点：区間ごとの平均からの二乗誤差（雑音の標準偏差で割ったもの）に、変化点1つあたり 3·log(n) の罰則を加えた量を最小にする分け方を厳密に求めます（PELT と同じ目的関数と解。週の数が200ほどなので枝刈りなしの最適分割で計算）。区間は最短4週。雑音の標準偏差は隣り合う週の差の MAD から見積もります（段差に強い）。
  3. 日付の幅：見つかった区間の平均に、同じ区間の残差を復元抽出して足したデータを100通り作り、同じ手順で探し直します。元の変化点から±8週以内で最も近いものの位置の5〜95%を幅、見つかった割合を再検出率としました。
  4. 報告の仕方の指標：週のうち、その指標が null または日報なしの日の割合にも同じ手法をかけます（雑音の下限 0.1）。
  5. 定義変更：meta.json の definition_changes を縦の破線で示します。「2024-08」のように月だけのものは月の1日に置いています。

限界

  • 平均の段差だけを探すので、ばらつきだけの変化や、ゆっくりした傾きは捉えません。罰則の強さで変化点の数は変わります。
  • 残差を独立とみなすブートストラップなので、週どうしの相関がある分、幅は狭めに出ます。
  • 週の中央値は、記載のある日だけから作ります。中間線越え等・公務船は null の日が多く、null の日がゼロに近い日なら、水準は高めに出ます。記載の割合が変わると見かけの水準も変わるので、下の図と合わせて読んでください。
  • 変化点が定義変更と重ならなくても、記録されていない運用の変更（数え方、公表方針）はあり得ます。
